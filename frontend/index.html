      Open questions for the project team

      1. Decided (27 Oct): chat-style interface with a chat list (new, rename, delete). The company profile is set up once and shared with all chats. The profile stays visible in a side panel. The 40-step ERP game stays in the code but is left out of the design for now.
      2. Saving chats: in the prototype, chats and the profile only exist while the page is open. The real system saves them per student. Should students also be able to delete their company profile and start again?
      3. Changing the profile later: “Change something” creates a new version, and all chats use the latest one. Is that the intended behaviour, or should older chats keep the version they started with?
      4. Required check-ins (student version): a short rating after the company profile and after the first new chat, plus the closing questionnaire. Enough, or too many?
      5. FREDi logo: six new concepts. Students pick one as the first step and the prototype then uses it everywhere. Should the team narrow them down to two or three before the test?
      6. THWS branding (not yet cleared): this draft uses the official THWS logo and THWS orange #FF6A00. Permission to use them in FREDi still needs to be confirmed. The FREDi logo is a first draft.
      7. One voice or several agents: do students only see “FREDi”, or should they see which agent answers (scenario agent, process coach, AP+ Navigator)? Try the switch in the design options. The guides call the click-path agent “AP+ Execution Agent”, the Sprint 4 slides “AP+ Navigator”.
      8. While FREDi responds: the prototype lets students keep typing but blocks sending. Is that right, or should messages queue?
      9. Later options: streaming replies, saved history and uploads are not shown. Confirm they stay out of release 1.
      10. Language: the prototype is in English. Do students also need a German version?
      11. Backend data: which scenario fields (order data, process steps, instructions) can the backend deliver?
      12. Student test: format, hosting and data protection: test via a link or in lectures? For a link, the prototype needs hosting. A GitHub Pages site is publicly reachable (private only with GitHub Enterprise Cloud), so the THWS branding should be cleared first. Proposal without any hosting: students open the prototype file from the e-learning course, download their results file at the end and upload it there; a script merges all files into one Excel workbook.
      13. Design source: is this code prototype fine for the handoff, or do we also need a Figma or Penpot file?

      Known issues

      1. Phone with doubled text size (edge case): the placeholder and the hint below the message input are cut off on the right. Everything else stays readable.
      2. Prepared answers: FREDi’s replies are scripted. Free text is understood only for the scenario card and a few keywords; otherwise FREDi says it is a prototype.
      3. Data stays in the browser: feedback, logo choice and the interaction log are stored locally in the browser used, until a Google Form is connected.
