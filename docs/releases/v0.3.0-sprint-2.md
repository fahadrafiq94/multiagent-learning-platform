# FREDi v0.3.0 — Sprint 2 Release Report

## Sprint

Sprint 2 — LangGraph Foundation

## Status

Completed
---
## Goal

Introduce LangGraph as FREDi's orchestration engine and establish a
provider-independent, testable workflow foundation for future specialized
agents.

## Summary

Sprint 2 introduced the first LangGraph workflow in the FREDi backend.

The workflow accepts a student message, validates and prepares the input,
selects a deterministic orchestration path, calls the existing Model Service,
and produces a structured final response.

The sprint intentionally uses placeholder paths rather than implementing the
full Scenario Agent, Process Coach Agent, and AP+ Navigator Agent. Those agents
will be implemented in the next sprint on top of the orchestration foundation
created here.

## Graph flow

```text
START
  |
  v
prepare_input
  |
  +-- invalid input --> finalize_response --> END
  |
  v
route_request
  |
  +-- scenario ------------> scenario_path
  +-- process reasoning ---> process_coach_path
  +-- AP+ navigation ------> ap_plus_navigator_path
  +-- unmatched -----------> fallback_path
                              |
                              v
                        model_response
                              |

                              v

# Architectural Decisions

## Deterministic Routing First

Sprint 2 uses deterministic routing rather than an LLM router.

This provides:

- Predictable behavior
- Straightforward unit testing
- Explicit fallback behavior
- Low latency
- No additional model call for route selection
- A stable baseline for later routing evaluation

> **Note:** The keyword router is a Sprint 2 orchestration mechanism, not the final pedagogical routing policy.

---

## Placeholder Paths Instead of Agents

The **Scenario**, **Process Coach**, and **AP+ Navigator** nodes are placeholder orchestration paths.

They demonstrate:

- Graph branching
- Route-specific model instructions

without prematurely implementing the full agent framework.

---

## Application Service Boundary

FastAPI depends on `OrchestrationService` rather than directly invoking a compiled LangGraph object.

This approach:

- Isolates LangGraph-specific behavior from the API
- Preserves a stable application contract

---

## Local Graph Visualization

The graph is exported as Mermaid source and styled locally.

Remote rendering is **not required**, supporting FREDi's:

- Local-first architecture
- Privacy-conscious design

---

# Not Included

Sprint 2 intentionally does **not** include:

- Full Scenario Agent behavior
- Full Process Coach Agent behavior
- Full AP+ Navigator Agent behavior
- Agent tools
- Agent memory
- Persistent LangGraph checkpoints
- PostgreSQL state persistence
- Retrieval-Augmented Generation (RAG)
- Document retrieval
- Checklist context
- Session summarization
- Student-adaptive behavior
- Production routing evaluation

These capabilities remain assigned to later sprints.
